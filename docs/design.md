# 設計筆記：為什麼是「定時囤貨機」

來源：2026-10-26 對「無上限自主演進」prompt 的可行性討論。

| 原始構想的問題 | 結論 |
|---|---|
| 規格通膨（嚴禁停下＋每輪加需求） | 通膨就是原料，人來減。放棄方向錨，改結構錨（FROZEN） |
| 品質熵增 | 唯一的敵人。用量出來的檢查守（測試、可刪、核心未動），不用模型判斷 |
| 自己考自己 | 審核降級為三題機械檢查，由腳本執行 |
| 定義「好」需要人 | 不定義。第 0 輪只抓競品痛點當選題偏好 |
| 沒有減法訊號 | 減法完全歸人，agent 只負責讓減法成本趨近零（卡片、flag、一鍵刪） |
| 「完成」沒定義 | 完成 = 時間到。最後 10% 強制打包 |
| 適用範圍 | 執行前先量類型與耦合，分 whole / module / plugin 三模式；不適用就降級不罷工 |

一句話：加法靠想像，減法靠回饋。AI 做前者，人做後者。
